# Папка данных — всё личное

Где лежит: папка, выбранная в приложении SEL (по умолчанию `~/Documents/SEL/data`), без git.
Программа (`portal/`, `desktop/`, `scripts/`) личного не содержит.

**Что в папке, какие колонки и откуда данные — в `desktop/data_readme.md`.** Приложение кладёт этот файл в папку
данных как `README.md` (перезаписывает при каждом обновлении), чтобы папку можно было читать без проекта, например
отдать LLM. Таблицу файлов ведём только там.

## Правила для разработчика
- Колонки — только в `desktop/schema.json`: приложение проверяет по нему заголовок. Поменяли колонки — поправьте
  и `data_readme.md`: тест проверяет, что там описан каждый CSV.
- Новые колонки — только в конец: старые файлы без них читаются, колонка появится при следующей записи.
- Убранные колонки — в `schema.json → dropped`: в старых файлах они пропускаются при чтении и исчезают при записи.
  Убранные файлы приложение просто не читает; переноса данных нет.
- Писать из кода только через `desktop/store.js` (`store.write` / `store.upsert`), из командной строки —
  `node scripts/csv.js`. Порядок колонок, сортировка, LF, числа без лишних нулей.
- `supplements.csv` различает строки по дате начала и названию: `upsert` по нему запрещён, пишут «Настройки».
- `meta.json` — только `alcohol_from`. План — в `plans.csv`, цели — в `targets.csv` / `goal_weight.csv`.
- `sync.json` — `{"fatsecret": ISO, "whoop": ISO}`: последнее успешное обновление сервиса (пишет `updater.js`); с него
  следующее обновление грузит данные (Whoop 14–365 дней, FatSecret 2–12 месяцев, 3 дня внахлёст), его показывает сводка.
