# «Что нового» и версии приложения — дизайн

Дата: 22.11.2026 · Статус: **реализовано** (22.11.2026; 1.0.0 ещё не выпущена — заметки в «Не выпущено»).
План — `docs/superpowers/plans/2026-11-22-release-notes.md`. Сверх дизайна: меню Mac по-русски, инструменты разработчика — только
при запуске из папки проекта

## Зачем
Приложение «Здоровье» раздаётся знакомым zip-файлом (до ~10 человек), автообновления нет. Тот, кто поставил новую
версию, должен с первого запуска понять, что изменилось. Вся история изменений должна быть доступна в любой момент.
Первая «настоящая» версия — 1.0.0: её заметки перечисляют все основные возможности. Всё на русском.

**Цели:** понятные заметки для внешних пользователей; окно с ними один раз после обновления; вся история в приложении;
ясное правило номеров версий; собрать версию без заметок нельзя.
**Не делаем:** автообновление и проверку новых версий в сети, обучение новичков (onboarding), английский язык.
**Провал, даже если всё работает:** окно мешает (появляется снова и снова или у новичка), в заметках «внутренности»
(CSV, IPC, имена файлов), заметки расходятся с тем, что на самом деле в сборке.

## Подходы к показу (выбран 1)
1. **Окно поверх страницы** при первом запуске новой версии — выбрано пользователем: человек остаётся, где был, окно
   показывается один раз; так делает большинство программ для Mac.
2. Открывать вместо «Сводки» страницу «Что нового» — уводит с привычного места.
3. Тихая метка в меню — легко не заметить.

## Номера версий — SemVer X.Y.Z, применительно к приложению
- **X (major)** — нужен шаг пользователя или нельзя вернуться на старую версию: несовместимая папка данных,
  переподключить сервисы, новые системные требования.
- **Y (minor)** — новые возможности, страницы, заметные изменения поведения.
- **Z (patch)** — исправления и мелкие улучшения без новых возможностей.
- 0.x — проверочные сборки (была 0.1.0 от 21.11.2026). Номер — в `desktop/package.json`, из него же имя zip.
- Каждому выпуску — тег `vX.Y.Z` в локальном git (никуда не пушим).

## Заметки — `desktop/CHANGELOG.md` (Keep a Changelog, по-русски)
- Версии сверху вниз — новые сверху: `## [1.0.0] — 2026-11-22`; вверху — `## [Не выпущено]`, туда копятся изменения
  между выпусками.
- Разделы в версии (только непустые, в этом порядке): `### Новое`, `### Изменено`, `### Исправлено`, `### Удалено`,
  `### Безопасность`. Пункт — `- …`, можно `**жирный**`.
- Правила текста (в шапке файла и CLAUDE.md): для пользователя, «что изменилось для вас»; один пункт — одна перемена;
  начинать с сути; без имён файлов и внутреннего устройства; при major — что нужно сделать.
- 1.0.0 — все основные возможности по страницам; черновик пишет Claude, пользователь вычитывает.
- 0.1.0 — короткая запись «первая проверочная сборка».

## Как работает
- `desktop/changelog.js` (Node): разбор CHANGELOG.md → `[{version, date, sections: [{title, items}]}]`; сравнение
  версий; какие версии показать; выпуск (переименовать «Не выпущено» в версию с датой). Файл входит в сборку.
- **Кто что видит.** Последняя показанная версия — `lastSeenVersion` в настройках приложения
  (`userData/config.json`, рядом с `dataDir`).
  - Новичок (нет `config.json` с папкой данных): окна нет, запоминаем текущую версию.
  - Обновился с 0.1.0 (папка есть, `lastSeenVersion` нет): считаем, что видел 0.1.0 → покажем 1.0.0.
  - Обычно: показываем все выпущенные версии новее `lastSeenVersion` и не новее текущей (пропустил несколько — все
    в одном окне, новые сверху).
  - `lastSeenVersion` = текущая записывается сразу при запуске (окно — только в этот запуск). До «Понятно» окно
    показывается и после перезагрузки страницы в этом запуске (страница перезагружается после обновления данных).
  - Проверочные запуски (`HEALTH_DOCUMENTS`) настройки не трогают; `HEALTH_WHATSNEW=<версия>` — показать окно,
    как будто последней была эта версия.
- **Окно** (`portal/whatsnew.js`, подключён на всех страницах после nav.js): `<dialog>` «Что нового в «Здоровье»», версии
  с датой («1.0.0 — 22 ноября 2026»), разделы и пункты; кнопки «Вся история» (→ страница) и «Понятно»; Esc — как
  «Понятно».
- **Страница «Что нового»** (`portal/whatsnew.html`): вся история (выпущенные версии не новее текущей), новые сверху;
  вне приложения — «есть только в приложении». В меню страниц её нет; ссылки: «Настройки» → «Версия 1.0.0 · Что нового»
  и меню Mac «Справка → Что нового в «Здоровье»» (вместо ссылок Electron).
- IPC: `health:whatsNew` → `{version, releases}` (что показать в окне; пусто — нечего), `health:whatsNewSeen`,
  `health:changelog` → вся история.
- **Выпуск:** `cd desktop && npm run release 1.0.0` — проверяет, что номер X.Y.Z больше текущего и «Не выпущено» не
  пусто; переносит заметки в `## [1.0.0] — <сегодня>`; ставит версию в package.json и package-lock.json; коммит
  «Выпуск 1.0.0» (только эти файлы) и тег `v1.0.0`. Потом `npm run dist:mac`.
- **Защита:** `npm run dist:mac` и тест не пропускают версию из package.json без своей датированной записи в CHANGELOG.

## Тесты
Разбор, сравнение версий, «кто что видит» (новичок / с 0.1.0 / пропущенные версии / уже видел), выпуск (перенос,
ошибки), CHANGELOG.md разбирается и в нём есть текущая версия, CHANGELOG.md — в `build.files`; окно и страница —
проверочным запуском (HEALTH_SMOKE + HEALTH_WHATSNEW, снимок).
