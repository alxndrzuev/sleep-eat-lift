# Ручные данные: что убрать, что вводить в приложении

## Зачем
Часть файлов папки данных заполнялась только из чата с Claude: в приложении ни поля, ни кнопки. Пользователь
не может их вести сам, и они устаревают (плитка «Самочувствие» с одной оценкой, план со ссылкой на удалённый Telegram).

Схема работы, на которую всё рассчитано: **приложение — смотреть и вводить данные; выводы делает LLM, читая папку
данных целиком.** Отсюда: всё, что пользователь ведёт, вводится в приложении; папка данных понятна без проекта
(есть описание файлов); свободный текст там, где его всё равно читает LLM, а не код.

## Цели
- Убрать то, что вести не будут: события кроме алкоголя, заметки и вывод по фото, самочувствие, анализы, талию и % жира.
- План — свободным текстом в «Настройках», с историей по датам.
- БАДы — в «Настройках»: добавить, прекратить с даты, удалить ошибочный; история — даты начала и конца.
- Числа плана, по которым приложение считает (сон, тренировки в неделю), — в «Цели» с той же историей.
- `README.md` в папке данных: какой файл о чём, колонки, источники, особенности — для LLM.

## Не цели
- Метки тренировок (`workout_labels.csv`) — не трогаем, обсуждаем отдельно.
- Выводы и разборы в приложении — их делает LLM.
- Разметка (markdown) в тексте плана — показываем как текст с переносами строк.

## Анти-цели
- Потерять данные при чистке: всё удаляемое сначала копируется в архив.
- Сломать папку данных у других пользователей (Windows-сборка, пустые файлы, старый `meta.json`).

## Подходы к хранению плана
- **`plans.csv` (start, text)** — выбран. Как остальные данные: запись через `store.js`, история по дате, тесты есть.
  Многострочный текст в ячейке CSV (в кавычках) — `parseCsv`/`quote` это уже умеют.
- Папка `plans/YYYY-MM-DD.md` — удобно читать глазами, но отдельный способ хранения со своими проверками.
- Массив в `meta.json` — история не в CSV, против правила проекта.

## Что делаем

### 1. Схема (`desktop/schema.json`)
- Удалить таблицы `checkins.csv`, `labs.csv`, `photo_notes.csv`.
- `body.csv` — убрать `waist_cm`, `bodyfat_pct` (остаются date, weight_kg, note).
- `events.csv` — остаётся только для алкоголя (колонки те же).
- `targets.csv` — в конец: `sleep_h`, `strength_wk`, `cardio_wk`.
- Новая `plans.csv`: `start`, `text`; ключ `start`; оба — текст.
- `supplements.csv` — колонки те же; различать строки по `start` + `name` (одной датой начинаются несколько).
  Запись — read → изменить → `store.write`, не `upsert` по `start`. *(решение builder'а — как именно сделать ключ;
  `scripts/csv.js upsert supplements.csv` не должен молча склеивать строки одной даты.)*

### 2. Перенос старой папки данных — кода нет (решение пользователя)
Приложение ничего не переносит. Папку данных основного пользователя Claude чистит один раз вручную после выпуска
(сначала копия в `<папка>/archive/2026-11-22/`): удалить `checkins.csv`, `labs.csv`, `photo_notes.csv`,
в `events.csv` оставить алкоголь, `body.csv` переписать по схеме, из `meta.json` убрать `plan`, `journal`,
`photos_summary`, `priorities`. План и цели сна/тренировок пользователь вносит сам в «Настройках».
У других пользователей лишние пустые файлы просто остаются — приложение их не читает.

### 3. «Настройки»
- **Цели**: к КБЖУ и весу добавить «Сон, ч», «Силовые в неделю», «Кардио в неделю».
  Правила те же: с даты, пустое — как в действовавшей цели. Пределы: сон 4–12, тренировки 0–14.
  В истории целей — новые колонки.
- **План**: поле «Действует с» (по умолчанию сегодня) и большое текстовое поле, заполненное текущим планом.
  «Сохранить» → строка `plans.csv` с этой даты (та же дата — заменить). История: дата, первая строка,
  «показать» (весь текст), «удалить».
- **БАДы**: таблица «сейчас» и «раньше» (название, доза, когда, зачем, с, по); форма добавления (название —
  обязательно, доза, когда, зачем, заметка, с даты); у текущих — «прекратить» (дата конца, по умолчанию сегодня),
  у всех — «удалить» (с подтверждением). Смена дозы — прекратить + добавить.
- IPC и `preload.js` — по образцу `saveTargets`/`removeTarget`; логика и проверки — в `settings.js` (тесты).

### 4. Страницы
- Сводка: карточка «План» — текст действующего плана (по `plans.csv` на сегодня), через `esc()`, переносы строк,
  в заголовке «с <даты>». Убрать: «Хорошая неделя», плашки приоритетов, «События», «Анализы», плитки
  «Самочувствие» и «Талия», график талии; подвал без «талия, силовые, анализы, события».
  Карточка «БАДы» остаётся; текст для пустой — «Добавьте в Настройках».
- Цели сна и тренировок — из действующей строки `targets.csv` (`dataset.js`), а не из `meta.plan`:
  сводка (плитки сна и тренировок), «Восстановление» (линия цели сна, по умолчанию 7,5).
- **Тренировки — две группы, у всех одинаково: силовые и кардио** (особого «Сквоша» больше нет, `DATA.k2` и выбор
  режима убрать). Силовые — силовые виды Whoop (как сейчас `STRENGTH`); прогулка — не тренировка; всё остальное,
  включая сквош и вид «не указан», — кардио. Кардио короче 20 минут — не тренировка (как прогулка: разминка на
  велосипеде после силовой). Группа «Другое» исчезает. Метки (`workout_labels.csv`) пока: strength → силовые,
  none → не тренировка, squash/cardio/other → кардио; что с ними дальше — отдельное обсуждение.
- «Фото»: убрать заметки к снимкам и общий вывод.
- `dataset.js`: не читать удалённые таблицы, `waist`; новые `plans`, цели сна/тренировок.

### 5. README папки данных
Шаблон в `desktop/` (в `build.files`), приложение кладёт его в папку данных как `README.md` при каждой сборке
`data.js` (перезаписывает). Содержание: назначение папки, каждый CSV — что в строке, колонки, источник (FatSecret,
Whoop, ввод в приложении, разметка алкоголя), особенности (день < 1200 ккал — незаполненный; день Whoop = день
после сна; шаги — за цикл; `activity` = вид не указан; как тренировки делятся на силовые и кардио), что такое `archive/`, `photos/`, `secrets/`
(не читать и не пересылать). `docs/07_формат_данных.md` ссылается на шаблон, без дублирования.

### 6. Документы и заметки
`CLAUDE.md`, `docs/07`, `README.md` проекта — новая схема, план и БАДы в «Настройках». `CHANGELOG.md` «Не выпущено»:
Новое (план и БАДы в настройках, цели сна и тренировок, описание папки данных), Изменено (тренировки — силовые и кардио), Удалено (самочувствие, талия,
анализы, события кроме алкоголя, заметки к фото), с пометкой, что удалённое лежит в `archive/`.

## Ограничения
- Репозиторий публичный: в коде, тестах, документах — никаких данных пользователя (названий БАДов, текста плана).
- CSV — только через `store.js`; новые колонки — только в конец.
- Тесты: `npm test` и `RENDER=1 npm test`; новая логика (перенос, настройки плана/БАДов/целей) — новые тесты.
