# Приложение «Здоровье» на Electron — дизайн

Дата: 21.11.2026 · Статус: **реализовано (v0.1.0, Mac)**, проверено пользователем 21.11 на Mac: запуск «как скачанное» (macOS блокирует → «Конфиденциальность и безопасность → Всё равно открыть», один раз), вход FatSecret через окно с обратным адресом `https://health.local/fatsecret` (oob не понадобился), загрузка года, фото. Whoop — проверен 21.11 отдельным приложением Whoop (обратный адрес https://health.local/whoop, год данных, автообновление автора на старом ключе не пострадало); политика конфиденциальности для экрана Whoop — docs/privacy-policy.html (опубликована на claude.ai) · Заменяет `2026-11-19-portable-archive-design.md` (архив с Python-движком)
· v1 — **только macOS**; **FatSecret и Whoop** подключаются в приложении, каждый по желанию

## Зачем

Портал автора хотят давать знакомым — **до ~10 человек**, без терминала и установки чего-либо. У кого-то
FatSecret, у кого-то Whoop, у кого-то оба. Electron даёт одно приложение со своим Chromium, окном и значком
и проверенный путь к подписи. Начинаем с Mac; Windows — когда версия для Mac обкатана.

## Цели

- Человек скачивает `Здоровье.app` в zip, открывает — появляется окно «Здоровье».
- Первый экран — **«Подключить FatSecret»** и **«Подключить Whoop»** (каждый по желанию): окно входа сервиса →
  «Allow» → окно закрывается само, данные за год загружаются. Ни терминала, ни ключей.
- Данные обновляются при запуске и по кнопке «Обновить» — по всем подключённым сервисам.
- Цели (ккал, Б/Ж/У, целевой вес) — на странице «Настройки».
- Фото формы — загрузка, выравнивание, сравнение — как у автора.
- **Модули независимы**: FatSecret (питание, вес), Whoop (сон, восстановление, пульс, шаги, тренировки), Фото — любой
  набор; страницы, пункты меню, плитки и блоки без данных не показываются.
- Данные — в `Документы/Здоровье/data/`: переживают обновление и удаление приложения, их легко скопировать.
- У автора всё как сейчас: портал из файла в Chrome, Python-скрипты, `auto_update.sh`, задачи Claude, Telegram.

## Не цели (v1)

- **Windows** — потом. Код пишем без привязки к Mac (пути через `path`, `app.getPath`), но не собираем и не проверяем.
- Telegram и разметка «похоже на алкоголь» в приложении (остаются у автора).
- Ручная разметка тренировок без вида (`activity`) — у автора она через Telegram; в приложении такие тренировки
  считаются «Другое».
- Автообновление (нужен хостинг и подпись) — новая версия скачивается вручную.
- Подпись: v1 без подписи (одно «Всё равно открыть»); Apple Developer ($99) — когда дойдём до раздачи.
- Разборы Claude, план, журнал для пользователей приложения.

## Анти-цели

- Личное автора (CSV, `meta.json`, документы, ключи доступа, фото, история git) внутри приложения.
- Ключи доступа пользователя уходят куда-то, кроме его компьютера и самого сервиса.
- Логика портала (расчёты, страницы) расходится между приложением и порталом автора.
- Окно приложения грузит что-то из интернета, кроме страниц входа FatSecret/Whoop и запросов к их API.

## Ограничения (проверено 21.11.2026)

- **FatSecret, тариф Basic:** 5000 запросов в день на ключ приложения, пользователей без ограничений; дневник и вес
  доступны. Обновление одного человека — 4 запроса, первое подключение — 24. Дневник — только OAuth 1.0. Ограничение по
  IP — для OAuth 2.0; поддержка: OAuth 1.0 — без ограничений по IP.
- **Условия FatSecret** (риски приняты пользователем): ключи нельзя раскрывать третьим лицам (ключ приложения внутри
  приложения — серая зона); контент без пометки «хранить бессрочно» — не дольше 24 часов (храним историю — серая зона);
  приложение должно быть «общедоступным». Обязательно: **«Powered by fatsecret»** на экранах с их данными, ссылка на их
  условия и фраза «Пользуясь приложением, вы принимаете условия fatsecret Platform API», «Не медицинская консультация».
- **Whoop:** официальный API v2 (`/v2/cycle`, `/v2/recovery`, `/v2/activity/sleep`, `/v2/activity/workout`, постранично
  через `next_token`), OAuth 2.0 с `offline` — `refresh_token` обновляется сам и меняется при каждом обновлении
  (сохранять новый). Cloudflare у Whoop режет стандартный User-Agent — нужен свой. `state` — 8 символов. Вход — только на
  `redirect_uri`, зарегистрированный в приложении Whoop. Ограничения Whoop для неодобренных приложений (сколько
  участников может подключиться) — **проверить в кабинете разработчика Whoop до раздачи**.
- **Ключи приложений — отдельные** от тех, на которых работает `auto_update` автора; их заводит автор:
  FatSecret — `data/secrets/fatsecret_app.json` (`consumer_key`, `consumer_secret`), Whoop — `data/secrets/whoop_app.json`
  (`client_id`, `client_secret`; в приложении Whoop зарегистрировать `redirect_uri = https://health.local/whoop`).
  Не в git; в приложение попадают при сборке.
- **Без подписи** Mac показывает «Не удалось проверить…» → «Конфиденциальность и безопасность → Всё равно открыть»
  (один раз).
- **Node.js** не установлен — ставим через Homebrew (только для сборки). Electron поддерживает три последние мажорные
  версии (~полгода каждая) — пересобирать раз в полгода.

## Подходы (рассмотрены)

1. **Electron, расчёты портала — общий JavaScript** — выбран. Один набор страниц и расчётов для приложения и портала
   автора; на двух языках остаётся только выгрузка из FatSecret и Whoop.
2. Electron + Python внутри — отклонён: тяжелее, подпись сложнее.
3. Архив + Python-движок + окно Chrome/Edge — отклонён для 10 человек; подробно — в прежнем дизайне.

## Как устроено

### Папки в репозитории

```
portal/                 ← страницы — общие для портала автора и приложения
  dataset.js            ← НОВОЕ: расчёт DATA из сырых таблиц (бывшая логика build_portal.collect)
  nav.js                ← НОВОЕ: меню, «Обновить» и «Настройки» в приложении
  settings.html         ← НОВОЕ: подключения, цели (только в приложении)
desktop/                ← НОВОЕ: приложение Electron
  package.json          ← electron, electron-builder (devDependencies); node_modules/ — не в git
  main.js               ← окно, протокол app://, меню ОС, IPC
  preload.js            ← мост для страниц: window.health.{…}
  store.js              ← CSV в Документы/Здоровье/data: чтение, upsert, сырые таблицы → data.js
  oauthwin.js           ← окно входа сервиса: открыть, перехватить обратный адрес, закрыть
  fatsecret.js          ← OAuth 1.0 и выгрузка (порт scripts/fatsecret_api.py)
  whoop.js              ← OAuth 2.0 и выгрузка (порт scripts/whoop_api.py)
  updater.js            ← обновление всех подключённых сервисов
  photosfs.js           ← файлы фото в data/photos для страницы «Фото»
  build/                ← значок
scripts/build_portal.py ← теперь пишет сырые таблицы (как store.js); расчёты — в dataset.js
dist/                   ← сборки (не в git)
```

### Данные пользователя

`Документы/Здоровье/data/` (`app.getPath('documents')`): те же CSV и раскладка, что у автора (`SCHEMA` в
`scripts/lib.py` — источник истины; `desktop/schema.json` — копия, тест следит за расхождением), `secrets/fatsecret.json`
и `secrets/whoop.json` (только ключи доступа пользователя), `photos/`, `data.js`. Создаётся при первом запуске.

### Один расчёт для всех: `data.js` = сырые таблицы, `dataset.js` = расчёт

- `data.js`: `const RAW = {tables: {"body.csv": [...], ...}, meta: {...}, modules: [...], updated: "YYYY-MM-DD"}` —
  строки CSV с числами вместо строк (как сейчас `build_portal.load`).
- `portal/dataset.js`: `Dataset.build(RAW) -> DATA` — всё, что сейчас считает `build_portal.collect`. Страницы
  подключают `../data/data.js`, `dataset.js`, `nav.js`, `common.js` — и дальше работают с `DATA`, как сейчас.
- Python (`build_portal.py`) и Electron (`store.js`) пишут `data.js` одного формата. Тест сверяет `Dataset.build` на
  данных автора с прежним `collect` (эталон снимаем до переноса).

### Окно и протокол

- Одно окно (`contextIsolation`, `sandbox`, без `nodeIntegration`), меню ОС минимальное.
- Протокол `app://` (`protocol.handle`): `app://h/portal/**` → страницы внутри приложения; `app://h/data/data.js` и
  `app://h/data/photos/**` → из `Документы/Здоровье/data`; остальное — 404. Пути страниц те же, что у автора.
- Внешние ссылки — `shell.openExternal`; навигация окна — только `app://`.

### Подключение сервисов (общая схема)

Окно входа (`oauthwin.js`): отдельная сессия (`partition` на сервис), без `preload`; открывает адрес авторизации и ждёт
перехода на обратный адрес (`will-redirect`/`will-navigate`); перехватывает его (страница не грузится), отдаёт параметры,
закрывается. Закрыли окно без «Allow» — «не подключено», без ошибки; повторное «Подключить» начинает заново.

- **FatSecret (OAuth 1.0):** `request_token` с `oauth_callback=https://health.local/fatsecret` → окно →
  `oauth_token` + `oauth_verifier` → `access_token` → `secrets/fatsecret.json` → загрузка 12 месяцев. Если FatSecret
  не примет такой callback — `oob`: пользователь копирует код со страницы FatSecret в поле на «Настройках». Какой путь
  сработал — записать сюда после проверки.
- **Whoop (OAuth 2.0):** адрес авторизации со `scope = offline read:recovery read:cycles read:workout read:sleep
  read:profile read:body_measurement`, `state` (8 символов), `redirect_uri = https://health.local/whoop` → окно →
  `code` (+ проверка `state`) → обмен на токены → `secrets/whoop.json` → загрузка 365 дней.
- «Отключить» — удалить ключи доступа сервиса; данные в CSV остаются.
- Тексты ошибок: «Нет связи с <сервис>, данные со вчера. Попробуйте позже» · «Доступ к <сервис> пропал — подключите
  заново» · «<сервис> ответил ошибкой: …».

### Обновление

При запуске и по «Обновить», по каждому подключённому сервису независимо (ошибка одного не мешает другому):
FatSecret — текущий и прошлый месяц (питание, вес); Whoop — последние 14 дней (дни и тренировки; удалённые в Whoop
тренировки за этот период убираются, как в `whoop_api.py`). Каждый сервис пишет свои CSV только после всех своих
запросов; затем `data.js`, страницы перезагружаются. Одно обновление за раз; ошибки — в строке статуса по сервисам.

### Страницы

- `nav.js`: Сводка; Питание (есть питание или вес); Тренировки и Восстановление (есть данные Whoop); Фото; Настройки и
  «Обновить» — только в приложении (`window.health`).
- Сводка без пустого: приоритеты — `meta.priorities`, цель по тренировкам — `meta.plan.workouts`, целевой вес —
  `goal_weight.csv`, цели ккал/белка — `targets.csv` на сегодня; блоки «План», «Хорошая неделя», «БАДы», «События»,
  «Анализы», «Журнал» — только непустые; совсем пусто → «Подключите FatSecret или Whoop».
- Подвал в приложении на страницах с данными FatSecret: «Powered by fatsecret», «Условия fatsecret Platform API»,
  «Не медицинская консультация». На страницах с данными Whoop — «Данные Whoop» и «Не медицинская консультация».
- «Настройки»: FatSecret и Whoop — по блоку (статус, «Подключить»/«Отключить», последнее обновление, ошибка; у FatSecret —
  поле кода для `oob`); цели (новая строка в `targets.csv` / `goal_weight.csv` с сегодняшней даты); версия;
  «Открыть папку с данными».
- «Фото»: в приложении папка известна (`data/photos`) — выбор папки не нужен; `preload` даёт объект с интерфейсом
  `FileSystemDirectoryHandle`, который использует `photos_app.js`, поверх `data/photos`. У автора в Chrome — как сейчас.

### Сборка (Mac)

- `cd desktop && npm run dist:mac` → `dist/Здоровье-<версия>-mac.zip` (arm64 + x64, ad-hoc подпись).
- В приложение: `portal/` (без `data.js`), `desktop/*.js`, `schema.json`, `fatsecret_app.json` и `whoop_app.json` —
  только поля ключей приложения.
- **Проверка приватности** после сборки: в `app.asar` нет `data/`, `docs/`, `tests/`, `CLAUDE.md`, `data.js`, и ни
  одного значения из `data/secrets/*.json`, кроме ключей приложения. Нарушение — сборка падает.
- Версия — `package.json`, видна в «Настройках».

## Тесты и проверка

- Python (`unittest`): `build_portal` пишет `RAW`; `desktop/schema.json` совпадает с `lib.SCHEMA`.
- JS чистой логики — `jsc`: `Dataset.build` (сверка с эталоном прежнего `collect`), `Nav.items`, подпись OAuth 1.0
  (`fatsecret.signedUrl` совпадает с `fatsecret_api.signed_url`), разбор ответов Whoop в строки CSV (совпадает с
  `whoop_api.py` на одних и тех же JSON).
- Electron — `node --test` в `desktop/`: хранилище, протокол, обновление с заглушками сервисов, настройки, фото,
  проверка приватности.
- Отрисовка — headless Chrome (`RENDER=1`): портал автора не изменился; «только FatSecret», «только Whoop» — без
  пустого.
- Вручную: собранный `.app` с пометкой «скачано из интернета», подключение FatSecret и Whoop учётками автора, фото.

## Порядок работ

1. Страницы: `dataset.js`, `nav.js`, без пустого, приоритеты и цели из `data/` — сразу польза автору.
2. `desktop/`: Node, Electron, окно, протокол, хранилище, `data.js`.
3. Окно входа и FatSecret.
4. Whoop.
5. «Настройки», «Обновить», подвалы.
6. Фото в приложении.
7. Сборка Mac, проверка приватности, значок.
8. Проверка как у пользователя, документация.

## Решения, принятые мной (проверить)

- Данные — `Документы/Здоровье/data`.
- Расчёты портала переезжают из Python в `portal/dataset.js`; `build_portal.py` пишет сырые таблицы.
- Протокол `app://` вместо `file://`.
- Обратные адреса — несуществующие `https://health.local/fatsecret` и `https://health.local/whoop`, перехватываются окном.
- Whoop: первая загрузка — 365 дней, обновление — 14 дней (как `auto_update`).
- Mac — zip с `.app` (не dmg).
- Прежние дизайн и план архива помечены «заменён»; из них сюда перешли меню `nav.js`, скрытие пустого, приоритеты и цели
  из `data/`.
